# 棋譜おこし — iPhone PWA

将棋アプリの画面録画から盤面の変化と合法手を照合し、KIF棋譜を作るWebアプリです。GitHub Pagesからアプリ本体を配信し、動画の読み込みと認識は端末内で行います。動画・棋譜をアップロードするサーバーや外部AI APIは使いません。

公開先: https://mor1kku.github.io/kifu-okoshi-pwa/

## iPhoneで使う

1. Safariで公開先を開き、共有メニューから「ホーム画面に追加」します。
2. 通信できる場所で「オフライン用にアプリを保存」を押し、完了を確認します。初回のダウンロードは約28MBです。
3. 「写真」または「ファイル」から動画を選びます。iCloud上だけにある動画は先に端末へダウンロードしてください。
4. 1手目が動く前の初期配置が表示される時刻と盤の範囲、アプリの種類、先後の向きを指定します。画面の下側が先手とは限りません。
5. 解析を実行し、結果を確認・修正してKIFを保存します。解析中は画面を開いておいてください。

更新は画面下の「アプリの更新を確認」から行えます。新版を取得した後、保存済みの棋譜を残して画面を開き直します。ほかのタブやホーム画面版が開いている場合、解析中、未保存の手修正がある場合は更新を止めて案内します。v1.2.2以前には更新ボタンがないため、オンラインで一度開いた後、このサイトのSafariタブとホーム画面版をすべて閉じて開き直してください。サイトデータを消す必要はありません。アプリ自体の版は画面上部、保存結果を作った版は結果欄に表示します。

画面を閉じると途中保存して一時停止し、同じ画面に戻ると自動で再開します。iOSは非表示のWebページを休止するため、画面を閉じたままの解析継続は保証できません。ページを再読み込みした場合やOSがアプリを終了した場合は、同じ動画を選び直し、「保存済みの解析を開く」→「途中から再開」を使います。通常は約5秒間隔で途中経過を端末内に保存します。手動停止した場合は自動再開せず、手修正した結果からの再開にも対応していません。OSが保存領域を消去する場合があるため、結果はKIF・JSONでも保存してください。

## 対応範囲と検証状況

v1.2以降は、将棋ウォーズの盤面の変化を各フレームの小さな画像で確認し、変化がある区間と直後の確認フレームを間引かずに読み取ります。標準の12 fps設定のままで速い区間に追従します。読み取り不足が残る場合は結果に明示します。更新後は画面上部の「v1.2.3」を確認して、元動画を最初から解析してください。以前の途中結果から再開しても、その前に抜けた手は復元されません。

v1.2.1では、すでに駒が動いた盤面を初期配置として登録することを防ぎ、最初に動いた側が先後の設定と合わない場合にも確認を促します。同じ動画を選び直した場合は開始時刻を保持し、別の動画には前の盤面設定を流用しません。設定JSONに `startTime` がある場合は開始時刻も読み込みます。保存結果には解析時のバージョンを表示します。

v1.2.2では、画面復帰時の自動再開、完了時に手数表示が古いまま残る不具合、盤面が大きく進むと読み取り不足を警告しない不具合を修正しました。途中停止は「途中結果」と表示します。結果JSONには終了状態、停止理由、動画の長さ、解析した時刻、デコードしたフレーム数・時刻間隔を残します。想定より手数が少ない場合は「JSON保存」の結果を使い、設定・デコード・駒の認識のどこで止まったのかを調べられます。動画の画像データはJSONに含めません。

v1.2.3では、盤の外側まで含む枠で誤認識が続く問題に対し、初期配置の同色・同種の駒字が各マスに収まっているかを確認します。枠のずれを検出した場合は開始時に修正を促します。緑の線を盤の9×9のマス目に合わせ、数字・外枠・駒台は含めないでください。アプリ内から更新を適用する操作も追加しました。

- 平手の初期配置から始まる画面録画に対応します。棋桜・将棋ウォーズ用の認識設定と汎用設定があります。
- 速度が変わる動画でもフレーム時刻を使って読み取ります。指し手の中間局面が録画に存在しない場合や、盤が隠れる場合には誤認識・欠落が起こり得ます。
- 未知の盤面テーマ・アプリ、途中局面からの開始、すべての動画形式への対応は保証していません。WebCodecsで読めない形式は理由を表示して停止します。
- 2026-10-30にPCのChromeで、棋桜の136手と将棋ウォーズの42手を実動画から認識し、正解棋譜との一致を確認しました。将棋ウォーズでは停止・ページ再読み込み・再開も検証しました。
- v1.2では、60 fpsで2フレームずつ進む合成動画の6手、1フレームの駒打ち・応手を含む合成動画の7手、実動画を16倍速にした区間の7手もChromeで一致しました。共通認識器で既存の棋桜136手・将棋ウォーズ42手も再照合しています。
- v1.2.1では、ショート動画の画面録画（約10.8秒）を、初手前の開始位置・後手が下の向き・盤面範囲で設定し、Chromeで20手すべてを映像と照合しました。オフライン、停止再開、KIF/JSON保存も確認済みです。
- v1.2.2では同じ短縮動画で、手動停止・再読み込み・再開に加え、二通りの画面復帰を挟んでも20手が一致しました。
- v1.2.3の調査では、41.6秒のフル版が2手になるという結果JSONを確認し、その盤面範囲を短縮版に適用すると同じ誤った2手になることを再現しました。新しい初期検証はその枠を拒否し、正しい枠ではChromeで20手の一致を維持しています。フル版の動画本体は未提供のため、後半の精度は未検証です。
- オフラインでの起動、短い区間の解析、修正、KIF/JSON保存、結果の再表示もChromeで確認済みです。
- **iPhone実機での速度・メモリー・発熱・動画形式ごとの動作は未検証の試作版です。** PCでの検証はiPhoneでの動作保証ではありません。

## ローカルビルド

Node.js 22、Python 3.12を使用します。

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
npm ci --ignore-scripts
npm test
python -m pytest -q
npm run prepare:pwa
npm run build:pwa
python -m http.server 8002 --bind 127.0.0.1
```

PCのブラウザーで `http://127.0.0.1:8002/dist-pwa/` を開きます。PWAはAPIサーバーなしで動作します。`prepare:pwa` は固定版の公式Pyodideパッケージを取得し、SHA-256を確認します。再ビルド時の旧成果物は `.local/pwa-builds/` に退避します。

公開リポジトリには実動画・正解棋譜・動画由来のテストfixtureを含めません。そのため、非公開の棋譜またはfixtureを使う5テストは公開ソースではskipされます。合成盤面を使う認識・速度・向き・途中再開テストは実行できます。高速動画の回帰テストには、60 fpsで1〜2フレームしか表示されない局面、3手目から急に速くなる区間、短い駒打ちと応手、元の盤面へ戻る演出、動画から局面が欠落した場合の警告を含みます。開始位置・先後の誤設定や、別の歩が交互に演出で隠れた場合の誤停止も検証しています。

ブラウザー用の高速テスト動画は `python -m scripts.make_fast_fixture` で `.local/fast-validation/` に生成できます。PlaywrightとChromeがある環境では、`python -m scripts.test_pwa_browser --serve --video .local/fast-validation/fast-wars.webm --reference .local/fast-validation/fast-wars.kif --settings .local/fast-validation/fast-wars.json --full --offline --resume` で端末内解析・オフライン・再開・KIF保存を検証できます。同じコマンドの `fast-wars` を `fast-drop` に置き換えると、1フレームの駒打ちと応手を検証できます。

`--visibility-resume` を加えると、非表示通知後に保存を待って戻る場合と、保存完了前に戻る場合の自動再開も検証します。これはPCブラウザー上で通知を再現するテストで、iOS実機のプロセス休止を再現するものではありません。

`python -m scripts.test_pwa_update --old 旧v1.2.1の配信フォルダー --new dist-pwa` では、旧版がキャッシュされた状態からの更新、保存結果の維持、別タブがある場合の更新保留、更新後のオフライン起動をChromeで検証します。

## GitHub Pages

Settings → Pages → Build and deployment → Source を **GitHub Actions** にします。`main`へのpush、またはActionsの「Build iPhone PWA」の手動実行でテスト、ビルド、デプロイします。

配信するのは `dist-pwa/` の静的ファイルだけです。相対URLで動作するため、リポジトリ名を変えてもビルドの変更は不要です。元動画・正解棋譜・`.local/`・fixtureを公開しないでください。

## 構成

- `backend/recognition.py` / `records.py`: PC版と共通の認識器と棋譜処理
- `backend/browser_bridge.py`: ブラウザー向けのフレーム入力・途中保存・復元
- `pwa/worker.js`: Mediabunnyで動画を逐次デコードし、PyodideでPython認識器を実行
- `pwa/local-engine.js` / `storage.js`: 端末内処理、IndexedDB保存、中断・再開
- `pwa/sw.js`: アプリと解析エンジンのオフライン保存
- `frontend/`: 盤面指定、結果確認・修正、KIF保存の画面
